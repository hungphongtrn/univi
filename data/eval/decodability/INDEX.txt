================================================================================
ARCHITECTURAL FINDINGS
================================================================================

Three issues identified:

[HIGH PRIORITY] Fixed output dimensions (1000×160)
  - Works for 10s clips, fails for variable-length audio
  - Causes 2× time-axis stretch for 5s clips
  - Result: mel correlation drops to 0.57 for short clips
  - Fix: Use dynamic output_width based on duration

[MEDIUM PRIORITY] Frequency-axis stretching (80→160)
  - Introduces double interpolation artifacts
  - Spectral centroid error up to 274 Hz
  - Fix: Keep output_height=80 (no stretching)

[CRITICAL PRIORITY] Griffin-Lim phase recovery
  - Fails to recover meaningful phase
  - Reconstructed waveform is noise (SNR < 0 dB)
  - Fix: Use mel-direct route or neural vocoder

================================================================================
WHAT THE TESTS SHOW
================================================================================

PIXEL ENCODING: ✓ EXCELLENT (0.994 correlation)
  - PNG encoding/decoding is faithful
  - 8-bit quantization acceptable on log-mel scale

MEL PRESERVATION: ✓ GOOD (0.89-0.96 correlation for 10s clips)
  - LANCZOS resize introduces ~2.2 dB average error
  - Signal structure preserved

PHASE RECOVERY: ✗ FAILURE (SNR -0.90 dB)
  - Griffin-Lim cannot reconstruct phase
  - Results in pure noise

TIME-AXIS HANDLING: ✗ POOR for variable-length audio
  - Fixed 1000-frame output mismatches clip durations
  - 5s clips get warped (mel correlation drops to 0.57)

================================================================================
INTERPRETATION FOR TRAINING
================================================================================

Audio training in Univi may fail due to:

1. RENDERING itself: ✗ Unlikely (mel preservation is good)
2. Phase recovery: ✓ Possible (Griffin-Lim fails, but model doesn't use audio)
3. Pixel decoding: ✗ Unlikely (pixel encoding is excellent)
4. Time-axis mismatch: ✓ Possible (for <10s clips)
5. Model's visual grounding: ✓ Most likely (is the model learning to read pixels?)

RECOMMENDATION:
  Run eval_ablation.py to test visual grounding ability
  Check if model loss on audio is due to rendering or learning capability
